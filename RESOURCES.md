# TerraSim Resources and Tooling

What Claude Code (or a teammate) can use on this project, its real status, and when to use it. The tool
list started from the Shroud/SurferStopper RESOURCES.md; the ideas and rules here are TerraSim's own.
Last checked 2026-10-24.

## Ground rules

- None of the design or review tools are runtime dependencies. The frontend runs with all of them missing.
- Runtime libraries (Rive, MapLibre, three.js, Motion) are vendored into `frontend/vendor/`, so the site
  needs no build step and no CDN. Map tiles and imagery are the one thing that needs the internet.
- Ask before paid plans, credentials or API keys (Gemma / Google AI, a map provider), system-wide installs,
  GitHub Actions secrets or permissions, or hooks that run downloaded binaries.
- Project-scoped skills live in `.claude/skills/` and are committed so every teammate gets the same ones.
- PRODUCT.md is product truth; DESIGN.md (written at the end of the first frontend build) is the design
  source of truth. Skill output is advice: check it against those files and AGENT.md before applying it.
- Test browsers: one at a time, with a time limit, always closed. Use `frontend/tools/browser.mjs`, never
  launch Chrome or Edge directly from a script.

## Available now (built into Claude Code, no setup)

| Resource | Use it for | When |
|---|---|---|
| `/security-review` | Security review of pending changes | Before merging anything touching auth, inquiries/messages, uploads, or API calls |
| `/code-review` | Correctness review of the diff or a PR (`/code-review high`, `--fix`) | Before each merge to `main` |
| `/simplify` | Cleanup pass for reuse, simplicity and efficiency | After a feature works, before review |
| `run` skill | Launching the frontend and driving it | After any UI change |

## Frontend runtime (in `frontend/`, vendored)

| Resource | Version | Use it for | Notes |
|---|---|---|---|
| [Rive](https://rive.app/docs/runtimes/web/web-js) (`@rive-app/canvas`) | 2.47.0 | State-machine animations: the general "working" grid while a request is sent, and the logo mark | `.riv` files are **generated by code** in `frontend/tools/rive/` (no editor or login needed), from type and property keys extracted from [rive-runtime](https://github.com/rive-app/rive-runtime) (MIT). Editor-made files can replace any of them if they keep the same state machine and input names. Every animation has a non-Rive fallback; if a file fails to load the UI still works. |
| [MapLibre GL JS](https://maplibre.org/) | 6.15.0 | The globe, the 3D map, outlining land | Replaced Leaflet (2026-10-24) so the house can stand in 3D. Vector tiles and 3D buildings from [OpenFreeMap](https://openfreemap.org/) (OpenStreetMap data, no key). |
| [three.js](https://threejs.org/) | 0.186.1 | The 3D house on the map (a MapLibre custom layer) and the walkthrough | Vendored ES module plus `PointerLockControls`. |
| Esri World Imagery | n/a | Satellite imagery, the default basemap | No key; attribution shown. Check Esri's terms before production use. |
| [Motion](https://motion.dev/) (vanilla build) | 14.6.0 | Interface transitions and scroll-linked moves | Respects `prefers-reduced-motion`. |
| [Playwright](https://playwright.dev/) | 1.64.1 (dev only) | Screenshots, Rive checks and interaction tests | Uses the Chromium already in the Playwright cache (build 1243) or Edge, so nothing is downloaded. It cannot test real map tiles offline or the backend; those stay manual. |

Update the vendored copies with `npm install` then `npm run vendor` inside `frontend/`.
